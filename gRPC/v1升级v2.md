# gRPC-Gateway v2 迁移指南

本指南旨在帮助网关用户从 v1 迁移到 v2。有关专门针对 v2 所做的所有更改的详细信息，请参阅[原始问题。](https://github.com/grpc-ecosystem/grpc-gateway/issues/1223)

以下行为默认值已更改：

## protoc-gen-swagger 已重命名为 protoc-gen-openapiv2

有关更多信息，请参阅[原始问题](https://github.com/grpc-ecosystem/grpc-gateway/issues/675)。除了新名称之外，对用户而言唯一真正的区别是 proto 注释略有不同：

```
import "protoc-gen-openapiv2/options/annotations.proto";
```

代替

```
import "protoc-gen-swagger/options/annotations.proto";
```

和

```
option (grpc.gateway.protoc_gen_openapiv2.options.openapiv2_swagger) = {
```

代替

```
option (grpc.gateway.protoc_gen_swagger.options.openapiv2_swagger) = {
```

Bazel 规则已重命名 `protoc_gen_openapiv2`。

## OpenAPI 注释中的示例字段现在是一个字符串

这是一种 `google.protobuf.Any`类型，但它只用于 JSON 表示，它破坏了一些工具，用户通常不清楚它是如何工作的。它现在是一个字符串。该值被逐字复制到输出 OpenAPI 文件中。请记住转义字符串中的任何引号。

例如，如果您有一个如下所示的示例：

```
example: { value: '{ "uuid": "0cf361e1-4b44-483d-a159-54dabdf7e814" }' }
```

它现在看起来像这样：

```
example: "{\"uuid\": \"0cf361e1-4b44-483d-a159-54dabdf7e814\"}"
```

有关更多示例，请参见示例 protos 中的[a_bit_of_everything.proto](https://github.com/grpc-ecosystem/grpc-gateway/blob/master/examples/internal/proto/examplepb/a_bit_of_everything.proto)。

## 我们现在默认使用 camelCase JSON 名称

有关更多信息，请参阅[原始问题](https://github.com/grpc-ecosystem/grpc-gateway/issues/375)和[原始拉取请求](https://github.com/grpc-ecosystem/grpc-gateway/pull/540)。

如果您想恢复到旧行为，请使用以下命令配置自定义封送拆收器 `UseProtoNames: true`：

```
mux := runtime.NewServeMux(
	runtime.WithMarshalerOption(runtime.MIMEWildcard, &runtime.HTTPBodyMarshaler{
		Marshaler: &runtime.JSONPb{
			MarshalOptions: protojson.MarshalOptions{
				UseProtoNames:   true,
				EmitUnpopulated: true,
			},
			UnmarshalOptions: protojson.UnmarshalOptions{
				DiscardUnknown: true,
			},
		},
	}),
)
```

要更改 OpenAPI 生成器行为以匹配，请 `json_names_for_fields=false`在生成时设置：

```
--openapiv2_out=json_names_for_fields=false:./gen/openapiv2 path/to/my/proto/v1/myproto.proto
```

如果使用 Bazel 规则，请设置 `json_names_for_fields=False`.

## 我们现在为所有字段发出默认值

有关更多信息，请参阅[原始问题](https://github.com/grpc-ecosystem/grpc-gateway/issues/233)。

如果您想恢复到旧行为，请使用以下命令配置自定义封送拆收器 `EmitUnpopulated: false`：

```
mux := runtime.NewServeMux(
	runtime.WithMarshalerOption(runtime.MIMEWildcard, &runtime.HTTPBodyMarshaler{
		Marshaler: &runtime.JSONPb{
			MarshalOptions: protojson.MarshalOptions{
				EmitUnpopulated: false,
			},
			UnmarshalOptions: protojson.UnmarshalOptions{
				DiscardUnknown: true,
			},
		},
	}),
)
```

## 我们现在默认支持 google.api.HttpBody 消息类型

该 `runtime.SetHTTPBodyMarshaler`功能已消失，现在默认启用。如果您出于某种原因不希望 `HttpBody`消息受到尊重，您可以通过使用不包含 `runtime.JSONPb`在的封送拆收器覆盖默认封送拆收器来禁用它 `runtime.HTTPBodyMarshaler`：

```
mux := runtime.NewServeMux(
	runtime.WithMarshalerOption(runtime.MIMEWildcard, &runtime.JSONPb{
		MarshalOptions: protojson.MarshalOptions{
			EmitUnpopulated: true,
		},
		UnmarshalOptions: protojson.UnmarshalOptions{
			DiscardUnknown: true,
		},
	}),
)
```

## runtime.DisallowUnknownFields 已被移除

现在，所有编组设置都从配置的编组器继承。如果您希望禁止未知字段，请配置自定义封送器：

```
mux := runtime.NewServeMux(
	runtime.WithMarshalerOption(runtime.MIMEWildcard, &runtime.HTTPBodyMarshaler{
		Marshaler: &runtime.JSONPb{
			MarshalOptions: protojson.MarshalOptions{
				EmitUnpopulated: true,
			},
			UnmarshalOptions: protojson.UnmarshalOptions{
				DiscardUnknown: false,
			},
		},
	}),
)
```

## WithLastMatchWins 和 allow_colon_final_segments=true 现在是默认行为

如果您之前指定了这些，请删除它们，因为这是现在的默认行为。有关更多信息，请参阅[原始问题](https://github.com/grpc-ecosystem/grpc-gateway/issues/224)。

没有解决方法，因为我们认为这是对规范的正确解释。如果这会破坏您的应用程序，请仔细考虑定义服务的顺序。

## 错误处理配置已大修

`runtime.HTTPError`, `runtime.OtherErrorHandler`, `runtime.GlobalHTTPErrorHandler`,`runtime.WithProtoErrorHandler`都过去了。围绕 gRPC 状态类型的使用重写了错误处理。如果您想配置网关如何处理错误，请使用 `runtime.WithErrorHandler`和 `runtime.WithStreamErrorHandler`。要处理路由错误（类似于删除的 `runtime.OtherErrorHandler`），请使用 `runtime.WithRoutingErrorHandler`.
